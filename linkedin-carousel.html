The problem
Static wasn't
enough
🕐
24-hour lag
GitHub Actions ran once a day. New listens appeared stale by the time the chart updated. On album release day, I wanted live numbers.
🔑
API key exposure
Injecting a Last.fm API key via sed in CI keeps it out of git, but still ships it to every visitor's browser.
📦
No persistence
Each rebuild hit the API fresh. No time-series history. A single API failure and the whole chart reverted to defaults.
🌸
Release day energy
On Florescence release day I wanted to watch the numbers climb in real time — not refresh 24 hours later.

"I need a proper server. Something that polls, persists, and serves live data."

— me, probably at 11pm on a Tuesday
